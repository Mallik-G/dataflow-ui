# EditEntityMappingsPage Component Documentation

## Overview

The `EditEntityMappingsPage` component is a React component that provides a comprehensive interface for managing data transformations between raw (source) and curated (target) data entities. It's a critical part of the data pipeline management system, allowing users to define how raw data columns should be mapped to curated data columns, add transformations, and manage metadata.

## Purpose

This component serves as the primary interface for:

- **Column Mapping**: Mapping raw data columns to curated data columns
- **Data Transformation**: Defining rules for data transformation and validation
- **Metadata Management**: Managing column descriptions and documentation
- **Entity Configuration**: Setting up entity-level metadata and control columns
- **Data Lineage**: Maintaining traceability between raw and curated data

## Key Features

### 1. Column Mapping Management

- **Raw to Curated Mapping**: Maps columns from raw data to curated data
- **Auto-mapping**: Automatically suggests mappings based on column name similarity
- **Manual Override**: Allows manual adjustment of mappings
- **New Column Creation**: Enables creation of new curated columns

### 2. Control Columns

The component automatically manages system control columns:

- `_ingest_timestamp`: When data was ingested
- `_source_system`: Source system identifier
- `_record_status`: Data validation status
- `_update_timestamp`: Last update time
- `_batch_id`: Processing batch identifier
- `_created_by`: Record creator
- `_updated_by`: Last updater

### 3. Column Descriptions

- **Auto-generated Descriptions**: AI-generated descriptions for columns
- **Manual Descriptions**: User-editable column descriptions
- **System Descriptions**: Fixed descriptions for control columns

### 4. Data Persistence

- **Auto-save**: Automatically saves changes to backend
- **Transformation Storage**: Stores all transformation rules
- **State Recovery**: Restores previous state on component reload

## API Endpoints

### GET `/api/raw-schemas/{entityName}`

**Purpose**: Fetches schema information for a raw entity
**Response**:

```typescript
{
  success: boolean;
  schema: {
    schemaAttributes: string[] | Array<{name: string}>;
  };
}
```

### GET `/api/raw-schemas/{entityName}/column-metadata`

**Purpose**: Fetches column metadata including descriptions and data types
**Response**:

```typescript
{
  success: boolean;
  columnMetadata: Array<{
    columnName: string;
    description: string;
    isGenerated: boolean;
  }>;
}
```

### GET `/api/transformations/{entityName}`

**Purpose**: Loads previously saved transformations
**Response**:

```typescript
{
  transformations: {
    mappings: Mapping[];
    columnRules: Record<string, any>;
    operatorRules: Record<string, any>;
    concatenationRules: ConcatenationRule[];
    entityNLPRules: any[];
    columnDescriptions: Record<string, string>;
    curatedEntityName: string;
    curatedAttributes: string[];
  };
}
```

### POST `/api/transformations/save`

**Purpose**: Saves transformation configuration
**Request Body**:

```typescript
{
  entityName: string;
  transformations: {
    entityName: string;
    curatedEntityName: string;
    rawAttributes: string[];
    curatedAttributes: string[];
    mappings: Mapping[];
    columnRules: Record<string, any>;
    operatorRules: Record<string, any>;
    concatenationRules: ConcatenationRule[];
    entityNLPRules: any[];
    columnDescriptions: Record<string, string>;
    fileData: FileData;
    newColumns: string[];
    entityLevelMetadata: {
      controlColumns: string[];
      controlColumnsCount: number;
      note: string;
    };
  };
}
```

## Key Functions

### `createInitialMappings(rawCols, curatedCols)`

**Purpose**: Creates initial column mappings based on name similarity
**Parameters**:

- `rawCols`: Array of raw column names
- `curatedCols`: Array of curated column names
  **Returns**: Array of Mapping objects
  **Logic**: Uses fuzzy matching to suggest initial mappings

### `updateMapping(idx, field, value)`

**Purpose**: Updates a specific mapping field
**Parameters**:

- `idx`: Index of the mapping to update
- `field`: Field to update ("raw" or "curated")
- `value`: New value for the field
  **Side Effects**: Triggers auto-save if applicable

### `deleteMapping(idx)`

**Purpose**: Removes a mapping from the list
**Parameters**:

- `idx`: Index of the mapping to delete
  **Validation**: Prevents deletion of control columns

### `addMapping()`

**Purpose**: Adds a new empty mapping for creating new columns
**Returns**: Updates mappings state with new empty mapping

### `saveNewColumn(idx)`

**Purpose**: Saves a newly created column
**Parameters**:

- `idx`: Index of the new column mapping
  **Validation**: Ensures column name is provided and not a control column

### `autoSaveMappings(currentMappings, currentColumnDescriptions, newlySavedColumn)`

**Purpose**: Automatically saves transformation state to backend
**Parameters**:

- `currentMappings`: Current mapping state
- `currentColumnDescriptions`: Current column descriptions
- `newlySavedColumn`: Name of newly saved column (optional)
  **Side Effects**: Persists all transformation data to backend

## Best Practices

### For Developers

1. **State Management**: Always use the provided state setters
2. **API Calls**: Handle errors gracefully and provide user feedback
3. **Validation**: Validate inputs before processing
4. **Performance**: Use auto-save sparingly to avoid excessive API calls

### For Users

1. **Column Naming**: Use descriptive, consistent naming conventions
2. **Descriptions**: Add meaningful descriptions for better documentation
3. **Control Columns**: Don't modify system control columns
4. **Save Frequently**: Changes are auto-saved, but verify important changes

## Common Issues and Solutions

### Issue: Mappings not loading

**Cause**: Entity name not found or schema not processed
**Solution**: Verify entity exists and has been properly uploaded

### Issue: Auto-save not working

**Cause**: Network issues or backend errors
**Solution**: Check network connection and backend logs

### Issue: Control columns appearing editable

**Cause**: State not properly initialized
**Solution**: Refresh component or check control column logic
