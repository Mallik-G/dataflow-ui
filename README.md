Product Requirements Document (PRD)
Nexa Data Lineage Canvas – React Flow Interactive Mapping
1. Product Overview

Nexa provides industry-specific Target Data Models (Gold layer) and uses an LLM/RAG-based engine to automatically map Silver-layer attributes to these target models, generating ETL code for Snowflake or Databricks.

To improve transparency, validation, and user experience, Nexa needs an interactive visual canvas that displays:

Data sources

Silver attributes

Target gold model entities

Column-level lineage connecting them

Transform logic applied between nodes

Validation/errors in mappings

Ability for users to adjust mappings visually

The canvas will be powered by React Flow, and its data model will be stored in the Nexa DB (YAML/JSON).

2. Goals & Objectives
Primary Goals

Provide a visual, intuitive representation of mappings between source attributes → silver → target gold models.

Expose column-level lineage and transformations used by the LLM-generated mappings.

Allow curation & correction of mappings directly on the canvas.

Enable auto-regeneration of ETL code based on the curated canvas.

Improve trust in the LLM/RAG mapping by making it transparent and reviewable.

Secondary Goals

Allow versioning of mapping configurations.

Allow exporting lineage diagrams (image, PDF, YAML).

Integrate with dbt, Databricks, Snowflake pipelines.

3. Scope
In Scope

React Flow canvas UI

Node types & edge types

Rendering lineage from YAML mapping config

Editing & saving mappings

Search, filter, navigation features

Validation & error highlighting

Integration with Nexa's backend (mapping YAML, metadata store)

Out of Scope

Full ETL code generation engine (already exists)

ML/LLM mapping logic itself

Source system metadata ingestion

4. Users
Primary Users

Data Engineers – validate LLM-generated mapping

Data Architects – review the Gold model population

Business/Analytics Leads – understand lineage

Platform Admins – manage models & metadata

5. User Stories
5.1 Core Stories

As a Data Engineer, I want to view the source → silver → gold lineage so I can verify mapping correctness.

As a Data Engineer, I want to click a target field and see its mapped inputs and transformations.

As a Data Engineer, I want to drag & connect nodes to fix incorrect mappings.

As an Architect, I want to visualize dependencies between gold entities.

As a Data Engineer, I want to save edits so that ETL code regenerates automatically.

As a user, I want to hide/show layers (source/silver/gold) to reduce clutter.

5.2 Advanced Stories

As a user, I want validation errors highlighted when transformations are missing or incompatible.

As a user, I want to export lineage as PDF/image.

As a user, I want to search for columns across all layers.

6. Functional Requirements
6.1 Canvas Rendering

The canvas will display three main zones/layers:

Source Systems

Silver Models

Target Gold Model

Each zone contains multiple nodes.

Edges represent:

Mappings

Transformations

Derived expressions

6.2 Node Types
Node Type	Description	Fields
SourceTableNode	Raw source data tables	name, schema, list of columns
SilverTableNode	Curated silver-layer tables	name, columns
GoldEntityNode	Target model entities	name, attributes
ColumnNode (optional)	Individual column	name, type, lineage details
TransformNode	Expression applied	expression, function list
6.3 Edge Types
Edge Type	From → To	Description
MapEdge	source col → gold col	Direct mapping
TransformEdge	source col → transform node	Shows transformation
DerivedEdge	transform node → target col	Shows output routing
LLMGeneratedEdge	special styling	Auto-generated by LLM/RAG
6.4 Interaction Behavior

Click node → show metadata panel on the right

Hover edge → show transformation or mapping rule

Double-click → open expression editor

Drag to connect → create new mapping

Delete key → remove mapping

Zoom/pan → standard React Flow behavior

6.5 Metadata Side Panel

For a selected target attribute:

Source columns used

Transformation logic

Data types

Sample values (optional future phase)

Validation rules

LLM confidence score (if available)

6.6 Validation Rules

Missing source mapping → red highlight

Type mismatch → orange

Expression errors → red

Orphan columns → gray faded

6.7 Saving & Versioning

YAML representation of canvas is saved back to DB.

Version history stored.

Undo/redo on canvas.

7. Data Structures & Backend Requirements
7.1 Mapping YAML Structure (Model)
gold_model: Customer
entities:
  - attribute: customer_id
    type: string
    mapped_from:
      - column: cust_id
        table: silver_customer
      - transform: "cast(cust_id as string)"
  - attribute: customer_age
    mapped_from:
      - transform: "date_diff('year', dob, current_date)"
        inputs:
          - table: silver_customer
            column: dob

7.2 Backend Endpoints
Method	Endpoint	Purpose
GET /lineage/:model	Load mapping YAML & metadata	
POST /lineage/:model	Save updated mapping YAML	
GET /metadata/tables	List source + silver tables	
GET /metadata/gold	Gold model definition

9. Technical Architecture
Front-End

React + TypeScript

React Flow v11

Zustand for canvas state

Monaco Editor for transformation editing

YAML parser (js-yaml)

ELK Worker for auto-layout

Backend

Existing Nexa backend with new APIs

PostgreSQL (or persistent metadata store)

Versioned YAML storage

LLM engine (existing) used only when user requests remapping

Performance Targets

Support 500+ nodes and 2,000 edges without UI lag

Canvas load < 4 seconds for median models

Rendering updates under 100ms

10. Non-Functional Requirements

Scalability: Must support large enterprise data models.

Security: RBAC for editing vs read-only viewing.

Audit: Log all mapping edits.

Accessibility: Keyboard shortcuts, zoom, contrast.

Browser Compatibility: Chrome, Edge, Safari.
